## Per-chapter scope

The model is the same for every chapter (pilot spec §1–3):
- Prose and maths are copied verbatim.
- Maple admonitions become Python admonitions using `import chaosbook as cb`.
- Figures are regenerated by `creators/python/<chapter>/fig_*.py` and get
  "· code" links.
- An exercise include is ported with Python wording, plus a lab button.
- The chapter's manifest rows are filled in.
- Zero Maple mentions.

## Order and rationale

**disc2d → cont1d → cont2d → cont3d → fractals → practice → appendices →
close-out.**

- Following book order keeps forward references simple. cont3d reuses the
  Hénon map (disc2d) and the Lorenz-map idea (disc1d); fractals reuses
  attractors from disc2d and cont3d.
- The package grows steadily: map tools come in disc2d, then flow tools in
  cont1d, cont2d and cont3d. Each chapter adds only what it needs (pilot
  rule: generic tools first, systems second).
- Every chapter is publishable when it lands. The site and the draft PDF
  update chapter by chapter, so review can run in parallel.
- **Alternative:** do fractals and practice (both small) first for quick
  wins. Not recommended: fractals benefits from the disc2d and cont3d
  attractors being available.

## Per-chapter execution template (each chapter's own plan follows this)

1. Package additions, with qualitative tests (`pytest tests/ -q` green).
2. Creators, split into 2–3 tasks by figure family; static twins and
   interactive assets; "· code" link on every figure.
3. Chapter conversion: front half, then back half.
4. Exercises include, lab notebook, and data and asset copies.
5. Manifest rows, `index.md` toctree, a fresh-dir Sphinx build (OneDrive
   jupyter-cache gotcha), a PDF build, and a visual check of the figures
   against the Maple originals.
6. Commit on main; push after verification.

Binding from the pilot retrospective: every number that is quoted, tabulated
or used as a figure anchor is **run and pasted, diffed against the book**.
Labels are mathtext, using the shared `book.mplstyle` and the size classes.

## Decisions (author, 2026-11-04)

2. **Delivery:** one branch and pull request per chapter (`py/<chapter>`),
   each stacked on the previous one; no version tags or releases.
3. **Interactive budget:** about three companions per chapter at most. Fewer
   is fine where more would not be sensible.
4. **About page:** the Python edition gets its own copy. It is expected to

5. **Text:** prose and mathematics are not touched, except where they speak
   specifically about Maple.

## Conventions for implementers (binding)

These are the pilot's conventions. Read `python/disc1d.md`,
`python/_includes/disc1d_exercises.md`, `python/lite/files/disc1d_lab.ipynb`
and `creators/python/disc1d/*.py` as worked examples before starting.

- **Tooling:** `C:/Users/mvr/cbenv2/Scripts/python` (plain `python` is not on
  PATH). Tests: `.../python -m pytest tests/ -q`. Never run recursive deletes
  (`rm -rf`) in this OneDrive repo; build Sphinx into a fresh short directory,
  e.g. `.../Scripts/sphinx-build -b html python C:/Users/mvr/cb_build/<name>`.
- **Text:** copy prose and maths verbatim from `maple/<chapter>.md`. Only
  sentences that speak about Maple, worksheets or Maple commands are reworded
  (to Python, the `chaosbook` package or the lab). Zero Maple mentions remain.
- **Code admonitions:** ````{admonition} Python` with `:class: python` and a
  ```` ```{code-block} python ```` inside, using `import chaosbook as cb`,
  numpy, scipy (`solve_ivp`, `brentq`/`fsolve`) and sympy for symbolic work.
  The code must run. Any output quoted in the text is RUN, and the real
  output is pasted into the report and diffed against the book.
- **Figures:** `creators/python/<chapter>/fig_<family>.py` loads
  `creators/python/book.mplstyle` and writes PNG at dpi=150 to
  `python/_static/<chapter>/`, using the same basenames as the Maple figures.
  Size classes: a panel in a 2-column subfigure is `(4.2, 3.2)`, or
  `(4.2, 4.2)` for a square phase plot; a single full-width figure is
  `(5.0, 3.5)`. Labels are mathtext (`$x_n$`, `$\lambda_1$`), with no
  frames on legends. Every figure in the chapter is followed by an
  `{only} html` paragraph
  `*[Code behind this figure](https://github.com/mvreeuwijk/chaosbook/blob/main/creators/python/<chapter>/<script>.py)*`.
  Hand-drawn schematics with no Maple script are copied from
  `maple/_static/<chapter>/`.
- **Interactive companions:** plotly HTML written to
  `python/_static/<chapter>/interactive/` with
  `include_plotlyjs="../../plotly.min.js"`, embedded beneath the static
  figure in a ```` ```{raw} html ```` iframe block (see `python/disc1d.md`).
- **Package:** generic tools first, operating on any user `f`. Bundled
  systems are examples. Every addition needs qualitative pytest tests and an
  export in `src/chaosbook/__init__.py`. Chapter-specific one-off machinery
  stays in the creators scripts.
- **Exercises:** `python/_includes/<chapter>_exercises.md` with the lab
  button. Maple worksheet links become pointers to the lab's starter cells.
  Data files go to `python/_static/exercises/` and
  `python/lite/files/data/`. The lab `python/lite/files/<chapter>_lab.ipynb`
  must pass
  `.../Scripts/jupyter nbconvert --to notebook --execute --stdout <lab> > NUL`.
- **Manifest:** fill `python_source` and `python_status` for every row of the
  chapter in `creators/porting_manifest.csv`.
- **Index:** add the chapter to the Text toctree in `python/index.md`.
